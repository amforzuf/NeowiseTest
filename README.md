# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Проверка решения

```sh
node --test
```

Тесты сами поднимают HTTP-сервер на свободном локальном порту. Установка пакетов и отдельный запуск приложения не нужны. Проверяются некорректный ввод, все три темы, все пять меток сбоя, восстановление после ошибки и некорректная структура ответа AI. Отдельный тест проверяет лимит ожидания и передачу сигнала отмены, даже если модель его игнорирует.

Для проверки страницы отправьте «Когда доставка?», затем по очереди заявки с метками `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`. После каждого сбоя тема и черновик должны быть пустыми и скрытыми, а сообщение — предлагать ручной разбор. Текст заявки остаётся в поле; следующая обычная заявка снова даёт черновик. Пустая строка и пробелы показывают подсказку без обращения к API.

Для проверки сетевого сбоя сначала получите черновик, остановите сервер и отправьте следующую заявку в уже открытой вкладке. Старый результат должен исчезнуть, ручной разбор — остаться доступным. Зависший HTTP-запрос страница прекращает через 5 секунд.

## Как устроено решение

`server.mjs` проверяет входной JSON до вызова модели. Ошибки ввода возвращают HTTP 400 и `{"status":"invalid_input"}`. Функция `triage` разбирает ответ AI и проверяет тему по списку `delivery`, `pricing`, `other`, а черновик — на строковый тип и непустое содержимое после `trim()`. В ответ API попадают только проверенные поля; дополнительные поля модели не могут изменить статус.

Ожидание модели ограничено таймером 300 мс: `Promise.race` завершает ожидание, а `AbortController` отменяет работу имитатора. Таймер очищается в `finally`. Ошибка, таймаут или неподходящий результат дают HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. `mock-ai.mjs` не изменён.

Страница очищает предыдущий результат при новой отправке, блокирует повторную отправку на время запроса и выводит ответ через `textContent`. При сбое API или сети менеджер видит предложение разобрать заявку вручную. Черновик не отправляется клиенту автоматически.

Польза для менеджера: меньше времени на подготовку типового ответа и меньше риска перепутать черновики разных заявок; эффект можно измерить медианным временем от открытия заявки до готового к отправке ответа и долей черновиков, принятых без правок.

Для разработки, проверки и подготовки тестов использован OpenAI Codex. Результаты запуска тестов и браузерных проверок перечислены в PR.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.
